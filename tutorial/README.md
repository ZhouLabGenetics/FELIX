# FELIX tutorial

A walkthrough for running GWAS with **FELIX** end-to-end on a small simulated dataset. 

By the end you will have:

- generated a simulated admixed cohort (200 individuals, 3 ancestries, 60 variants),
- packed the phased genotypes + local-ancestry calls into the **FELIXla** format,
- fit the Step 1 null model,
- run the Step 2 ancestry-aware association test, and
- read off ancestry-specific and joint p-values from the output.

Everything below uses only files generated by [`simulate_example.py`](./simulate_example.py).

## 1. Method brief overview

**FELIX** is a scalable, local-ancestry-aware GWAS framework for 
cohorts containing ancestrally admixed samples as well as homogeneous samples. 
It has two components:

- **FELIXla** — a compact, streamable storage format that packs phased
  genotypes together with per-haplotype local-ancestry calls, so
  ancestry-specific dosages can be read in a single pass at biobank scale.
- **FELIXassoc** — the association module. From one null mixed-model fit it
  tests, at every variant, both a shared-effect (homogeneous) model and an
  ancestry-specific (heterogeneous) model, while controlling for relatedness
  and case/control imbalance.

For every variant and every ancestry `j` (e.g. AFR / EUR / AMR) it reports:

- the per-ancestry effect `BETA_anc{j}` and `p.value_anc{j}` (does this variant
  matter *on AFR haplotypes*, *on EUR haplotypes*, …?),
- a shared `p.value_ancALL` (the standard, ancestry-collapsed signal), and
- a joint `P_cct_admixed` that combines the two via a Cauchy combination —
  robust to whichever regime dominates a locus.

You run the test once per cohort to get all of these.

## 2. Installation

There are two ways to install FELIX. Pick one:

| | **2A. Docker / Singularity** | **2B. Source install with pixi** |
|---|---|---|
| **We recommend** | ✅ **yes — start here** | when Docker is not available |
| effort | one `docker pull` | one command; a few minutes of downloading, no compiling |
| requires | Docker Desktop, or Singularity/Apptainer on HPC | nothing but `curl` — pixi brings its own R, compiler and htslib |
| results | identical software stack everywhere | bit-identical on `linux-64`; ~2–3 significant digits elsewhere (see the note at the end of 2B) |
| runs on | Linux and macOS natively (amd64 + arm64 image), Windows/WSL2 | Linux and macOS |

Both give you the same four things: the FELIX R package, the FELIXla
command `felixla`, the step wrappers
(`step1_fitNULLGLMM.R`, `step2_SPAtests.R`, `step3_LDmat.R`,
`createSparseGRM.R`), and `bgzip`/`tabix`.

### 2A. Docker / Singularity / Apptainer (recommended)

FELIX is distributed as a single Docker image with everything pre-built. It is
published as a multi-architecture image, so the same command gets you a native
build on `linux/amd64` (servers, HPC, Intel Macs) and on `linux/arm64`
(Apple Silicon):

```bash
docker pull lhu1/felix:latest
```

To run any command in the container against your current directory, prefix it with:

```bash
docker run --rm -v "$PWD":/work -w /work lhu1/felix:latest  <command>
```

> **Pinning the architecture.** Add `--platform linux/amd64` to `docker pull`
> and `docker run` to force the amd64 build everywhere — on Apple Silicon it
> then runs under emulation (slower, but it is the build the reference output
> in `example_outputs/` was generated with). Use it when you want every
> collaborator on a project to get the same last digits; otherwise leave it off
> and get the native build.

> **HPC / Singularity / Apptainer.** If you cannot use Docker, convert the same
> image to a `.sif` once and substitute `singularity exec` (or `apptainer exec`)
> for `docker run`:
>
> ```bash
> singularity pull FELIX_latest.sif docker://lhu1/felix:latest
> singularity exec --bind "$PWD":/work --pwd /work FELIX_latest.sif step1_fitNULLGLMM.R --help
> # Equivalent Apptainer commands:
> apptainer pull FELIX_latest.sif docker://lhu1/felix:latest
> apptainer exec --bind "$PWD":/work --pwd /work FELIX_latest.sif step1_fitNULLGLMM.R --help
> ```

### 2B. Source install with pixi (Linux and macOS)

Use this if Docker is unavailable (common on HPC login nodes) or if you want to
modify the FELIX source. It works the same way on Linux and on macOS
(both Apple Silicon and Intel).

#### What is pixi, and why?

[pixi](https://pixi.sh) is a package manager: a single self-contained program
that reads a list of dependencies (`pixi.toml` in the FELIX repository) and
downloads exactly those packages — R, the R libraries, a C++ compiler, htslib,
Python — into a private folder inside the FELIX checkout (`.pixi/`).

Three things this buys you:

- **You do not need to install anything else first.** No conda, no R, no
  compiler, no `sudo`. If you can run `curl`, you can install FELIX.
- **Nothing on your machine changes.** Everything lands in `FELIX/.pixi/`.
  Your system R and any conda environments are untouched, and uninstalling is
  `rm -rf FELIX/`.
- **Everyone gets the same versions.** The repository ships a `pixi.lock` that
  pins every package down to the exact build, for `linux-64`,
  `linux-aarch64`, `osx-64` and `osx-arm64`.

#### Step 1 — install pixi (once per machine)

```bash
curl -fsSL https://pixi.sh/install.sh | sh
```

This writes a single binary to `~/.pixi/bin/pixi` and adds that directory to
your `PATH` in your shell startup file. **Close and reopen your terminal**
(or `source ~/.bashrc` / `source ~/.zshrc`), then check it:

```bash
pixi --version
# pixi 0.76.1   (0.72 or newer is required; the installer above gives you a current one)
```

<details>
<summary>If curl fails with <code>(35) Peer reports incompatible or unsupported protocol version</code></summary>

Your `curl` is too old to negotiate modern TLS — common on CentOS/RHEL 7 login
nodes, where `curl 7.29` is built against NSS. Download the release with `wget`
instead. This picks the right build for your machine:

```bash
case "$(uname -s)/$(uname -m)" in
    Linux/x86_64)              ASSET=pixi-x86_64-unknown-linux-musl.tar.gz ;;
    Linux/aarch64|Linux/arm64) ASSET=pixi-aarch64-unknown-linux-musl.tar.gz ;;
    Darwin/arm64)              ASSET=pixi-aarch64-apple-darwin.tar.gz ;;
    Darwin/x86_64)             ASSET=pixi-x86_64-apple-darwin.tar.gz ;;
esac
mkdir -p ~/.local/bin
wget -qO- "https://github.com/prefix-dev/pixi/releases/latest/download/$ASSET" \
    | tar -xz -C ~/.local/bin pixi
chmod +x ~/.local/bin/pixi
export PATH="$HOME/.local/bin:$PATH"
pixi --version
```

Then make it permanent:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
```
</details>

<details>
<summary>If <code>pixi: command not found</code> after reopening the terminal</summary>

The installer could not edit your shell startup file. Add it yourself:

```bash
echo 'export PATH="$HOME/.pixi/bin:$PATH"' >> ~/.bashrc   # or ~/.zshrc on macOS
source ~/.bashrc
```

On macOS the default shell is zsh, so use `~/.zshrc`. If you cannot write to
your home directory, set `PIXI_HOME=/some/writable/path` before running the
installer, and add `$PIXI_HOME/bin` to your `PATH`.
</details>

#### Step 2 — get FELIX and build it

```bash
git clone https://github.com/ZhouLabGenetics/FELIX.git
cd FELIX
pixi run setup
```

`pixi run setup` does everything, printing as it goes:

1. reads `pixi.toml` / `pixi.lock` and downloads the environment into
   `.pixi/envs/default` (1.7–2.2 GB on disk, a few minutes on a good connection);
2. installs the `felixla` command from `tools/felixla/prebuilt/`;
3. installs `lintools` from CRAN (the one R dependency not packaged for conda);
4. installs the **prebuilt FELIX R package** from `binaries/` — a few seconds;
5. installs the four step wrappers as ordinary commands in the environment.

The first run is dominated by the download; the FELIX parts take seconds. Later
runs are a no-op — `pixi run setup` only redoes what changed (use
`FELIX_FORCE=1 pixi run setup` to force it).

<details>
<summary>What is prebuilt, and what happens if there is no binary for your platform</summary>

Two things ship prebuilt so that nobody has to compile:

| | file |
|---|---|
| the `felixla` command | `tools/felixla/prebuilt/<platform>/felixla` |
| the FELIX R package | `binaries/FELIX_<version>_<platform>.tgz` |

Prebuilt for `linux-x86_64` and `macos-arm64`. Both carry a runtime path
relative to the file itself, so they work from any checkout, and both are
verified to load before being accepted.

**If your platform has no binary, or the binary will not load, setup compiles
from source automatically.** That path needs **≥ 2 GB of RAM** and a few
minutes — one file (`SAIGE_fitGLMM_fast.cpp`, ~7,000 lines of Rcpp/Armadillo
templates) dominates it. On a cluster login node, where memory limits are
usually lower, the compiler is killed part-way through:

```
x86_64-conda-linux-gnu-c++: fatal error: Killed signal terminated program cc1plus
```

Any `Assembler messages: ... unknown pseudo-op` lines just above that are debris
from the half-written file, not a separate problem. If you hit it, get an
interactive compute node and re-run:

```bash
srun --mem=4G --cpus-per-task=1 --time=1:00:00 --pty bash   # Slurm
qrsh -l h_vmem=4G                                           # SGE/UGE
```

Measured on CentOS 7 (glibc 2.17): installing the prebuilt package takes **4
seconds and 240 MB**; compiling the same package takes **3m40s and 1.06 GB**,
and is killed outright at a 1 GB limit.

To force a source build anyway: `FELIX_FROM_SOURCE=1 pixi run setup`.
</details>

#### Using the installed commands

Two equivalent ways to reach the FELIX commands:

```bash
# (a) prefix each command with `pixi run`, from anywhere in the repo
pixi run step2_SPAtests.R --help

# (b) enter the environment once; then everything is a plain command
pixi shell
step2_SPAtests.R --help
felixla --help
exit                       # leaves the environment
```

`pixi shell` is the convenient one for a work session. It only changes the
`PATH` of that one shell.

#### About the prebuilt `felixla` binary

FELIXla is a C++ program. To save you a compile step, the repository ships it
prebuilt for the two most common platforms:

| directory | for |
|---|---|
| `tools/felixla/prebuilt/linux-64/` | Linux on x86-64 (nearly all HPC clusters and servers) |
| `tools/felixla/prebuilt/osx-arm64/` | macOS on Apple Silicon (M1/M2/M3/M4) |

`pixi run setup` copies the matching binary into the environment and runs it
to confirm it works. **If there is no prebuilt binary for your platform
(Intel macOS, ARM Linux), or if the prebuilt one does not run, setup falls
back to compiling them from `tools/felixla/src/` — which takes a few seconds
and needs nothing extra.** Either way you end up with working
`felixla` command; the log line tells you which path was taken:

```
Installing FELIXla into /home/you/FELIX/.pixi/envs/default/bin
  using the prebuilt linux-64 binary
  ok: felixla
```

The binary is linked with a *relative* runtime path (`$ORIGIN/../lib` on
Linux, `@loader_path/../lib` on macOS), so it finds the pixi environment's
`libhts` no matter where you cloned the repository.

```bash
rm -rf FELIX/          # removes FELIX and its entire environment
rm -rf ~/.pixi         # optional: removes pixi itself
```

## 3. Quick start

Each command below runs the complete workflow — simulated data → FELIXla pack
→ Step 1 → Step 2 — and writes `output/step2_results.tsv`. The runner creates
the simulated data inside the selected environment, so Docker and `.sif`
users do not need Python or NumPy on the host.

**Docker (Linux or macOS):** from this `tutorial/` directory after
`docker pull lhu1/felix:latest`:

```bash
bash run_example.sh
```

**Singularity / Apptainer (Linux / HPC):** from the repository root, create
the `.sif` once; then run the runner from `tutorial/`:

```bash
apptainer pull FELIX_latest.sif docker://lhu1/felix:latest
# Or: singularity pull FELIX_latest.sif docker://lhu1/felix:latest

cd tutorial
FELIX_BACKEND=apptainer SIF=../FELIX_latest.sif bash run_example.sh
# Or: FELIX_BACKEND=singularity SIF=../FELIX_latest.sif bash run_example.sh
```

**Pixi (Linux or macOS):** after `pixi run setup`, run this from the repository
root:

```bash
pixi run test
```

You can also enter `pixi shell`, `cd tutorial`, and run `bash run_example.sh`.
`run_example.sh` picks Docker unless the FELIX commands are already on `PATH`;
force the backend with `FELIX_BACKEND=docker`, `native`, `singularity`, or
`apptainer` (and use `SIF=/path/to/image.sif` for a non-default image path).

By default it packs from the FLARE VCF. To run the same example from the RFMix
`.msp.tsv` instead:

```bash
LA_SOURCE=rfmix bash run_example.sh
```

The rest of this document explains each step so you can adapt it to your own data.

## 4. Generate the example dataset

From inside this `tutorial/` directory:

```bash
python3 simulate_example.py
```

This produces, in `./example_inputs/`:

| file | what it is |
|---|---|
| `samples.txt` | 200 sample IDs, one per line |
| `phenotype.tsv` | quantitative trait `Y` + covariates `age, sex, PC1, PC2, PC3` |
| `genotypes.phased.vcf` | phased genotype VCF, 60 variants on `chr22` |
| `localanc.flare.vcf` | FLARE-format local-ancestry VCF (per-haplotype `AN1`/`AN2` calls) |
| `localanc.rfmix.msp.tsv` | the same calls in RFMix `.msp.tsv` form — an alternative to the FLARE VCF |
| `example_grm.{bed,bim,fam}` | PLINK files (same 60 variants, used by Step 1 for the GRM) |

The simulation is seeded. 
It prints the index of the *simulated causal variant* — variant **v31** (chr22:16150000),
which by construction has an **AFR-haplotype-specific** effect of ≈1.4 on `Y`.
We therefore expect FELIX to flag it in `BETA_anc1` / `p.value_anc1` /
`P_het_admixed`, but not in `p.value_anc2` / `p.value_anc3`.

## 5. Input file overview

Five files. Take 30 seconds to look at each.

**5a. Phenotype TSV (`phenotype.tsv`)** — tab-separated, one row per individual, with a header. `IID` must match the VCF sample IDs.

```
IID     age  sex  PC1      PC2      PC3      Y
S0000   35   0    -0.1256  -0.6511   1.5985  -0.4489
S0001   47   0    -0.6532  -0.2485   1.3443  -1.0543
...
```

For a **binary** trait, code cases as `1` and controls as `0`.

**5b. Phased genotype VCF (`genotypes.phased.vcf`)** — standard VCFv4.2 with **phased** genotypes (`0|1`, not `0/1`), one line per variant. Bgzipped + tabix-indexed for use (Step 0 does this).

```
#CHROM   POS       ID   REF  ALT  QUAL  FILTER  INFO  FORMAT  S0000  S0001  ...
chr22    16000000  v1   T    A    .     PASS    .     GT      0|0    0|0    ...
```

**5c. FLARE local-ancestry VCF (`localanc.flare.vcf`)** — same frame as the genotype VCF, with two extra `FORMAT` fields: `AN1` (ancestry of the `|`-left haplotype) and `AN2` (the right). Labels are integers `0..K-1`, documented in the header.

```
##ANCESTRY=<ID=0,Name=AFR>
##ANCESTRY=<ID=1,Name=EUR>
##ANCESTRY=<ID=2,Name=AMR>
#CHROM   POS       ID  REF  ALT  QUAL  FILTER  INFO  FORMAT       S0000      S0001
chr22    16000000  v1  T    A    .     PASS    .     GT:AN1:AN2   0|0:2:2    0|0:2:1
```

Sample IDs **must match** the genotype VCF (FELIXla matches them by ID and
keeps the intersection, in genotype-VCF order). FLARE produces this format
natively.

**5c-bis. RFMix local ancestry (`localanc.rfmix.msp.tsv`)** — the alternative
to 5c, if you called local ancestry with RFMix instead of FLARE. RFMix reports
ancestry per *interval*, with two columns per sample (`ID.0`, `ID.1`) in the
same haplotype order as the `|` separator in the phased VCF:

```
#Subpopulation order/codes: AFR=0	EUR=1	AMR=2
#chm   spos      epos      sgpos   egpos   n snps  S0000.0  S0000.1  S0001.0  ...
chr22  16000000  16020000  16.000  16.020  5       2        2        2        ...
```

You do **not** need to convert this to a FLARE VCF first — FELIXla reads
`.msp.tsv` directly (see 6b-bis). Both sources produce the same packed output
and the same association results.

**5d. PLINK files (`example_grm.{bed,bim,fam}`)** — used by Step 1 only, to build the GRM and pick variance-ratio markers. Any small SNP set works; it need not match the GWAS variants.

**5e. Sample list (`samples.txt`)** — plain text, one ID per line, no header.

## 6. Step 0 — pack the phased VCF + local ancestry into FELIXla

`felixla` collapses the phased genotypes and the local-ancestry calls into a
small set of binary files — the **FELIXla** format — that FELIX reads in a
single streaming pass, far faster than re-parsing two files per variant at test
time. It is one binary; the input flag you give it decides which local-ancestry
source it reads.

**6a. Index the genotype VCF**

```bash
docker run --rm -v "$PWD":/work -w /work lhu1/felix:latest bash -c "
  bgzip -c example_inputs/genotypes.phased.vcf > example_inputs/genotypes.phased.vcf.gz
  bgzip -c example_inputs/localanc.flare.vcf  > example_inputs/localanc.flare.vcf.gz
  tabix -f -p vcf example_inputs/genotypes.phased.vcf.gz
  tabix -f -p vcf example_inputs/localanc.flare.vcf.gz
"
```

(Only the genotype VCF has to be indexed if you are packing from RFMix.)

**6b. Pack — from a FLARE VCF**

```bash
mkdir -p packed
docker run --rm -v "$PWD":/work -w /work lhu1/felix:latest \
    felixla \
        --phase-vcf example_inputs/genotypes.phased.vcf.gz \
        --flare-vcf example_inputs/localanc.flare.vcf.gz \
        --n-ancestries 3 \
        --mac-threshold 20 \
        --make-felixla \
        --out packed/example
```

**6b-bis. Pack — from an RFMix `.msp.tsv`**

Same command, with `--rfmix-msp` in place of `--flare-vcf`:

```bash
docker run --rm -v "$PWD":/work -w /work lhu1/felix:latest \
    felixla \
        --phase-vcf example_inputs/genotypes.phased.vcf.gz \
        --rfmix-msp example_inputs/localanc.rfmix.msp.tsv \
        --n-ancestries 3 \
        --mac-threshold 20 \
        --make-felixla \
        --out packed/example
```

On this example the two produce identical ancestry masks and identical Step 2
results. `run_example.sh` will use the RFMix input if you set
`LA_SOURCE=rfmix`.

| flag | meaning |
|---|---|
| `--phase-vcf` | the phased genotype VCF/BCF (`0\|1`, not `0/1`) |
| `--flare-vcf` | the FLARE local-ancestry VCF/BCF (`FORMAT/AN1`, `FORMAT/AN2`) |
| `--rfmix-msp` | *instead of* `--flare-vcf`: an RFMix `.msp.tsv` |
| `--n-ancestries` | K, the number of local ancestries (max 32) |
| `--mac-threshold` | variants at or below this MAC are stored as sparse carrier lists, above it as dense bit vectors. Omit it to use `auto` = `ceil(n_samples / 32)`, which is what we recommend for real data; `felixla --recommend-mac-threshold --n-samples N` prints the value without running a conversion. |
| `--make-felixla` | the action: build a packed prefix |
| `--out` | output **prefix** — writes `packed/example.meta`, `packed/example.common.geno.bin`, etc. |

The single prefix `packed/example` is what you pass to Step 2 as `--FELIXlaPrefix`.

<details>
<summary>Other things the same binary can do</summary>

```bash
felixla --tractor-dosage-vcf dosage.vcf.gz --n-ancestries 3 --make-felixla --out packed/x
felixla --felixla packed/example --query chr22:16150000 --ref G --alt A
felixla --felixla packed/example --export vcf --out packed/example.roundtrip.vcf.gz
felixla --felixla packed/example --region chr22:16000000-16100000 --make-felixla --out packed/sub
felixla --phase-vcf g.vcf.gz --flare-vcf f.vcf.gz --n-ancestries 3 \
        --keep samples.keep --extract sites.pvar --make-felixla --out packed/subset
```

Run `felixla --help` for the full list.
</details>

## 7. Step 1 — fit the null GLMM

Step 1 fits the per-cohort phenotype model. **It does not use local ancestry** —
that enters only at Step 2. Run it once per cohort + trait and reuse it across chromosomes.

```bash
mkdir -p output
docker run --rm -v "$PWD":/work -w /work lhu1/felix:latest \
    step1_fitNULLGLMM.R \
        --plinkFile=example_inputs/example_grm \
        --phenoFile=example_inputs/phenotype.tsv \
        --phenoCol=Y \
        --traitType=quantitative \
        --invNormalize=FALSE \
        --covarColList=age,sex,PC1,PC2,PC3 \
        --qCovarColList=sex \
        --sampleIDColinphenoFile=IID \
        --outputPrefix=output/step1_example \
        --nThreads=1 \
        --LOCO=FALSE \
        --IsOverwriteVarianceRatioFile=TRUE
```

Produces `output/step1_example.rda` (the fitted null model) and
`output/step1_example.varianceRatio.txt`. On this toy dataset it finishes in
under a minute.

> With related individuals, additionally pass `--useSparseGRMtoFitNULL=TRUE` and a
> pre-computed sparse GRM via `--sparseGRMFile` / `--sparseGRMSampleIDFile`
> (build it with `createSparseGRM.R`). We skip it here — this simulation has no
> related samples.

## 8. Step 2 — run the ancestry-aware association test

This is where local ancestry enters.

```bash
docker run --rm -v "$PWD":/work -w /work lhu1/felix:latest \
    step2_SPAtests.R \
        --FELIXlaPrefix=packed/example \
        --chrom=chr22 \
        --is_admixed=TRUE \
        --number_of_ancestry=3 \
        --pvalcutoff_of_haplotype=0.000005 \
        --GMMATmodelFile=output/step1_example.rda \
        --varianceRatioFile=output/step1_example.varianceRatio.txt \
        --SAIGEOutputFile=output/step2_results.tsv \
        --LOCO=FALSE \
        --minMAF=0 \
        --minMAC=1
```

The flags that distinguish this from a standard SAIGE run:

| flag | meaning |
|---|---|
| `--FELIXlaPrefix` | the prefix from Step 0 (the packed FELIXla input) |
| `--is_admixed=TRUE` | turn on the ancestry-aware machinery |
| `--number_of_ancestry=3` | K (must match what you packed in Step 0) |
| `--pvalcutoff_of_haplotype` | if a per-ancestry haplotype-count association drops below this, also run the conditional refit on that haplotype |

Everything else is standard SAIGE Step 2. The result is `output/step2_results.tsv`.

## 9. Reading the output

One row per variant, wide format.

> **Use the `_c_` columns.** For every estimate FELIX reports two versions: a
> plain one and a `_c_` one. The `_c_` columns are the ones to report. When a
> variant's per-ancestry haplotype association passes
> `--pvalcutoff_of_haplotype`, FELIX re-tests it conditional on the haplotype
> and puts the conditional result in the `_c_` column; when it does not, the
> `_c_` column carries the unconditional value. So the `_c_` columns are always
> complete, and always the more appropriate estimate. The columns without `_c_`
> are the same tests with no conditional analysis applied.

**Fixed columns** — `CHR`, `POS`, `MarkerID`, `Allele1`, `Allele2`.

**Per-ancestry columns**, repeated for each ancestry `j = 1..K` plus an `_ancALL` block (the collapsed, homogeneous dosage):

| column | meaning |
|---|---|
| `AC_Allele2_anc{j}` / `AF_Allele2_anc{j}` | alt allele count / frequency on ancestry-`j` haplotypes |
| **`BETA_c_anc{j}` / `SE_c_anc{j}`** | **per-ancestry effect estimate and standard error — report these** |
| **`p.value_c_anc{j}`** | **per-ancestry p-value (SPA-corrected) — report this** |
| `Tstat_c_anc{j}` / `var_c_anc{j}` | per-ancestry score statistic and its variance |
| `BETA_anc{j}` / `SE_anc{j}` / `p.value_anc{j}` | the same quantities with no conditional analysis applied |
| `Tstat_anc{j}` / `var_anc{j}` | score statistic and variance, unconditional |
| `N_haplo_anc{j}` | number of haplotypes painted as ancestry `j` at this variant |
| `Pvalue_haplo_anc{j}` | haplotype p-value — what is compared against `--pvalcutoff_of_haplotype` |

For binary traits you also get `AF_case_anc{j}`, `AF_ctrl_anc{j}`, `N_case_anc{j}`, `N_ctrl_anc{j}`, `p.value.NA_anc{j}`, `Is.SPA_anc{j}`.

**Joint p-values**

| column | meaning |
|---|---|
| **`P_cct_admixed_c`** | **Cauchy combination of the two — the recommended primary p-value** |
| **`P_het_admixed_c`** | **heterogeneity test — captures *ancestry-specific* effects** |
| **`P_hom_admixed_c`** | **homogeneous (collapsed) test — the standard ancestry-agnostic p-value** |
| `P_cct_admixed` / `P_het_admixed` / `P_hom_admixed` | the same three with no conditional analysis applied |

## 10. Common errors and how to fix them

### Installation

| symptom | likely cause | fix |
|---|---|---|
| `pixi: command not found` right after installing pixi | the installer edited a startup file the current shell has not read | close and reopen the terminal, or `export PATH="$HOME/.pixi/bin:$PATH"` |
| `step2_SPAtests.R: command not found` after `pixi run setup` | you are outside the environment | prefix with `pixi run`, or enter it once with `pixi shell` |
| `ERROR: CONDA_PREFIX is not set` from an install script | the script was run directly | run it through pixi: `pixi run setup` |
| `curl: (35) Peer reports incompatible or unsupported protocol version` installing pixi | your `curl` is too old for modern TLS (CentOS/RHEL 7 ships 7.29 built on NSS) | use the `wget` fallback in [Step 1](#step-1--install-pixi-once-per-machine) |
| `Virtual package '__glibc >=2.28' does not match ... [__glibc=2.17=0, ...]` | you are on an old distro **and** your `pixi.lock` predates the glibc-2.17 pin | `git pull` to get the current lock. Do **not** set `CONDA_OVERRIDE_GLIBC` — it silences the check instead of fixing it, and installs binaries your machine may not be able to run |
| `fatal error: Killed signal terminated program cc1plus`, often with `Assembler messages: ... unknown pseudo-op` just above | the compiler was killed by the OOM killer; the assembler errors are debris from the truncated file | you should not normally compile at all — check that `binaries/FELIX_*_<your platform>.tgz` exists and that setup says "Installing the prebuilt FELIX R package". If you are on a platform with no binary, the source build needs ≥2 GB RAM: move off the login node (`srun --mem=4G --pty bash`) and re-run |
| `pixi run setup` sits on `-c SAIGE_fitGLMM_fast.cpp` for a long time | it is compiling from source, and near a memory limit it thrashes rather than failing cleanly | interrupt it; the prebuilt package installs in seconds instead. See the "What is prebuilt" note in [Step 2](#step-2--get-felix-and-build-it) |
| `pixi run setup` fails while compiling the R package | stale object files from an earlier, differently-configured build | `rm -f src/*.o src/*.so && FELIX_FORCE=1 pixi run setup` |
| `error: could not resolve ...` during `pixi install` | no network / blocked conda channels | pixi needs `conda-forge` and `bioconda` reachable; set `HTTPS_PROXY` if your site requires one |
| `expected a string, found table` pointing at `platforms` in `pixi.toml` | your pixi is older than 0.72 and cannot parse the per-platform glibc pin | upgrade pixi: `pixi self-update`, or re-run the installer in [Step 1](#step-1--install-pixi-once-per-machine) |
| `the prebuilt binary does not run here; falling back to a source build`, or `the prebuilt package does not load here; compiling instead` | no prebuilt matches your platform, or it was built against a different environment | nothing to do — this is the intended fallback and the source build follows automatically (see the memory note above) |
| p-values differ slightly from `example_outputs/` | CPU-specific OpenBLAS kernels change the floating-point summation order | expected; happens with Docker too |
| `docker: no matching manifest` | your Docker may be too old to read a multi-arch manifest, or the arch is not published | add `--platform linux/amd64`, or use the pixi source install |

### Running FELIX

| symptom | likely cause | fix |
|---|---|---|
| `... file does not exist` at Step 2 | wrong `--FELIXlaPrefix` (a file name instead of the prefix) | pass the prefix only, e.g. `packed/example`, not `packed/example.meta` |
| `chrom needs to be specified ... when using FELIXla as input` | `--chrom` missing | pass the chromosome exactly as in the VCF — here `--chrom=chr22`, not `22` |
| Step 1 hangs / OOMs on related samples | full GRM being built | pre-compute a sparse GRM and add `--useSparseGRMtoFitNULL=TRUE` |
| `Sample IDs do not match` at Step 2 | phenotype IDs disagree with the packed samples | check `packed/example.samples` matches the `IID` column (and is a subset) |
| Many `NA` p-values at low-MAC variants | per-ancestry MAC below `--minMAC` | expected — rare variants split across K ancestries; lower `--minMAC` if needed |
| unstable per-ancestry effect for one ancestry | very few haplotypes painted that ancestry | check `N_haplo_anc{j}` / `AC_Allele2_anc{j}`; ignore that arm if both are tiny |
| `FELIXla streaming step2 currently supports chromosome traversal only` | you passed `--idstoIncludeFile` / `--rangestoIncludeFile` | filter at the packing step with `felixla --region` / `--extract`, or post-filter the TSV |
| `felixla` reports fewer samples than expected | genotype and local-ancestry sample sets differ | FELIXla keeps the intersection in genotype-VCF order; check `packed/example.samples` |
| RFMix run gives different results from FLARE | the `.msp` haplotype columns are not in the phased VCF's `\|` order | RFMix must have been run on the same phased VCF; check `ID.0`/`ID.1` ordering |
| `FORMAT/AN1 value out of range` | `--n-ancestries` does not match the labels present | ancestry codes must be `0..K-1`; for RFMix, K must match the `#Subpopulation order/codes` header |
